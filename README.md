# Inventory Lab — «Магазин у дома»

Учебная игра по управлению запасами. Сделана для лекции «ИИ в запасах» (Forecast NOW!, ноябрь 2026).

**Играть:** https://inventory-lab.tsdpu.org/. Нужно любое имя и кодовое слово `запасы`; слово не секретное, это учебный стенд.

Вы — закупщик небольшого магазина. Игра длится 4 недели, в магазине 4 товара. Каждую неделю вы делаете заказ. Он приезжает к началу недели, затем приходят покупатели. Побеждает тот, у кого меньше потери в рублях:

- **упущенная маржа**: товара не хватило;
- **списания**: молоко портится за неделю;
- **деньги на полке**: остаток на конец недели стоит 5 % закупочной цены.

Спрос одинаков для всех игроков, поэтому результаты можно сравнивать. В таблице лидеров есть две опорные строки: **оракул**, который знает будущий спрос, и **наивная политика** «заказать столько, сколько продали на прошлой неделе».

## Чему учит мир

| Товар | Ловушка |
|---|---|
| Молоко | Неделя с нулевым остатком в истории занижает спрос: продажи ≠ спрос. Непроданное списывается |
| Чипсы | Промо объявлено заранее. Средние продажи его не видят |
| Вода | Упаковка по 6 шт., минимальный заказ 24 шт. |
| Кофе | Мёртвый запас: дорогой остаток, продаж почти нет |

## Три способа играть

1. **Самому в браузере.** При входе выдаётся короткий ключ участника, например `K7MQ-2XPA`. По нему можно вернуться в игру с другого устройства.
2. **С чат-ИИ.** Кнопка «Скачать данные (CSV)» выгружает всё, что видит игрок. Файл можно загрузить в любой чат-ИИ и спросить совета.
3. **Агентом.** Дайте агенту ключ и ссылку на инструкцию [`/agent.md`](https://inventory-lab.tsdpu.org/agent.md). Дальше он играет сам через HTTP API.

## Запуск у себя

Нужен только Python 3.11+, внешних зависимостей нет.

```sh
python app.py            # http://localhost:8080, база stand.db рядом
PORT=9000 STAND_DB=/tmp/s.db STAND_CODE=слово python app.py
python -m pytest -q      # тесты (нужен pytest)
```

| Файл | Что внутри |
|---|---|
| `sim.py` | мир: товары, спрос, правила раунда, опорные политики |
| `app.py` | HTTP API, ключи участников, CSV, инструкция для агента |
| `index.html` | страница игрока |
| `deploy.sh` | выкладка в Docker за nginx: `DEPLOY_HOST=<ssh-хост> ./deploy.sh` |

## Как расширить модель

Мир нарочно простой. Как его усложнить, решаете вы. Идеи для issue и pull request:

- **Задержки поставщика.** Заказ иногда приезжает на неделю позже. Как изменится страховой запас?
- **Сезонность и тренд.** Спрос на воду растёт к лету.
- **Неопределённость спроса.** Сейчас спрос одинаковый для всех. Можно разыгрывать его по seed и сравнивать стратегии на многих прогонах.
- **Срок годности партиями (FIFO).** Сейчас молоко живёт ровно неделю. Можно добавить товары, которые живут 2–3 недели.
- **Бюджет и место на складе.** Ограничение на сумму заказа или объём.
- **Свой мир.** Перенести описание товаров из `sim.py` в JSON или YAML и добавить аптеку, стройматериалы или электронику.
- **Разбор после игры.** Показывать, на чём игрок потерял больше всего по сравнению с оракулом.

Как предложить изменение:

1. Сделайте форк.
2. Поменяйте `sim.py` и добавьте тест в `test_sim.py`: оракул должен оставаться лучше наивной политики.
3. Откройте pull request и опишите, какую реальную ситуацию закупщика моделирует изменение.
